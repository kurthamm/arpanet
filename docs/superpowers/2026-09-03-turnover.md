## 5. Root causes found (tell Oscar; they explain his "finicky" ITS/IMP experience)

1. **H316 host interface dies if it transmits before the host side listens** (`hi_link_error()` in
   `h316_hi.c`, no retry). The NOC started IMPs 35 s before NCP daemons, killing every host port.
   Fix: NCPs before IMPs (`mini/noc-server.py`). Same class as the ITS/IMP marriage problem.
2. **NCP socket names**: `mini/noc/server/ncp.py` used unpadded `ncp1`; everything else expects `ncp01`.
   Only two-digit sources (ncp31, ncp16) ever worked, hence the fork's single-source fallback.
3. **ncpdov could not hold two connections on one listened socket**: hardcoded per-connection
   socket/link numbers, listen/open replies sent to a stale global client address, `destroy()` clearing
   a listener by connection index. Fixed in `mini/src/ncpd-ovREUSE/src/ncp.c` (eee7373, c30ca1e).
4. **ncp-telnet -s shared one libncp socket across fork** and lacked `setsid()`, so a parent exit
   HUP'd live sessions. Fixed in `mini/src/apps/telnet.c`.
5. Earlier branch (merged): KAIMP interrupt latch bug in pdp10-ka (PDP-10/its #2376), Chaosnet device
   must be enabled or ITS 1652 halts on first NCP open, ncpd timeouts too short for TELSER.
6. Oscar's 8-way TIP rotation "unreliability": NCPS entries for hosts 74 (LL-TX2) and 78 (CMU-10A)
   commented out while their IMP host ports were attached.

Since then I've been chasing why ITS refused those connections, and it turned out to be real bugs rather than timing:

1. The pdp10-ka binary I was using predates Lars's KAIMP interrupt fix (PDP-10/its #2376). Without it the IMP interrupt stays latched, the clock level starves, TELSER never spawns, and terminals die after any network activity. Rebuilding from lars/ncp fixed it.
2. ITS 1652 is built with the Chaosnet device, and disabling it in the SIMH config makes the kernel halt on the first NCP open. Enabling CH10 fixes that.
3. The Linux ncpd needed longer RFC/CLS timeouts for the TELSER handshake, and it was answering stale CLS with ERR, which made ITS drop live connections.
4. And one that may explain the "marry ITS and the IMP at exactly the right moment" problem you and Lars fought: the simulated H316 host interface dies permanently if the IMP transmits before the host side is listening. My NOC was starting IMPs 35 seconds before the NCP daemons, so every host port was dead on arrival. Starting the host side first fixes it.

With those, host 126 answers a real NCP Telnet from IMP 31 with the TELSER login banner. It's not finished, but it's the golden route you describe.

If you'd like to bring the work into your repo, I'd rather do it your way (your option two). My plan is to put every host back on IMP-routed sessions: native NCP for ITS, and your FEP method for the hosts without a working NCP (WAITS, UCLA, Multics, OS/360). I'll remove the terminal-line shortcut entirely so nothing can quietly fall back to it, restore your rotation of visitors across the eight TIP sources, and rename everything back to the Arpanet Recreation Project. It's your project and it should carry its name.

That said, if you'd prefer to keep the two repos separate, or to pick out only the parts you find useful, I would completely understand. I'm happy either way. What I don't want is to hand you code that undermines the thing you built the project to show.
